# 今日情报汇总看板 · 使用说明

一个信息汇总工具：**GitHub 涨星雷达** + **A股四维要闻**，支持每日自动更新。

**在线访问**：https://daily-intel-dashboard-27810.app.workbuddy.host/

## ✨ 每日自动更新（云端定时，不依赖 WorkBuddy）

**每天北京时间 08:00 由 GitHub Actions 自动执行**，与 WorkBuddy 是否打开、你的电脑是否开机**都无关**：

```
GitHub 服务器（cron 00:00 UTC = 北京 08:00）
   → 跑 daily_update.py（抓 GitHub 涨星 + 财经快讯 → 合并 → 归档 → 聚簇 → 时间线 → 周报 → 导出）
   → 三判据校验，不通过则等待限流窗口后自动补跑（最多 3 次）
   → 把 data/ 提交回仓库
   → 调 jsDelivr purge 接口刷新 CDN 缓存（否则最长会延迟 12 小时）
        ↓
页面打开时从 CDN 读取当天 JSON（拿不到就退回站点自带的 data/ 副本）
```

- 仓库：https://github.com/1JacobHE/daily-intel
- 数据源：`https://cdn.jsdelivr.net/gh/1JacobHE/daily-intel@main/`
- 查看运行记录 / 手动补跑：仓库 **Actions** 页 →「每日情报更新」→ Run workflow
- **不需要**为每天的数据更新重新发布前端：页面只负责读，数据在云端生成

> ⚠️ 已知限制：GitHub 的 schedule 在整点高峰可能延迟几分钟到十几分钟；仓库连续 60 天无提交会被
> GitHub 自动停用定时任务（本项目每天有提交，正常不会触发）。

想手动补跑时，双击 `run.bat` 即可（**可重复执行，同一天多次运行不会造成数据重复**）。

## 快速开始

```
双击 run.bat
```

它会依次执行：抓 GitHub 数据 → 抓财经快讯 → 合并 A股要闻 → 归档 → 打开看板。也可以手动执行：

```bash
python daily_update.py          # ★ 推荐的完整流程（上述全部步骤）
```

或单独执行各环节：

```bash
python github_star_radar.py     # 仅抓 GitHub 数据 + 重建日期索引
python news_fetcher.py          # 仅抓财经快讯（东财/新浪/同花顺）
python archive.py               # 仅归档到历史目录
start index.html                # 开看板
```

## 日期切换

看板顶部有日期选择器，可以切换查看任意一天的数据：

- **下拉框** 选择具体日期
- **‹ ›** 按钮前后翻一天
- **快捷按钮** 直接跳最近几天
- 切换时 GitHub 榜单和 A股要闻**同步切换**

### 历史数据怎么累积

| 目录 | 内容 |
|---|---|
| `data/history/YYYY-MM-DD.json` | GitHub 单日榜单归档（含内联中文解读） |
| `data/news_history/YYYY-MM-DD.json` | A股要闻单日归档 |
| `data/history/index.json` | 日期索引，日期选择器读它 |

**每个交易日运行一次 `run.bat`，历史就自动累积一天。** 某天没跑脚本，那天在日期列表里就不存在，看板会提示"该日期无归档数据"。

### 数据是怎么自动更新的

```
每天 08:30 定时任务触发（daily_update.py 编排 8 步）
      │
      ├─ 1. github_star_radar.py   抓 GitHub 涨星（三维度 + 快照增量）
      ├─ 2. news_fetcher.py        抓财经快讯 + 五轴评分 + 噪声压制
      ├─ 3. merge_market_news()    合并自动快讯 + 人工深度调研
      ├─ 4. archive.py             归档到 data/history/ 和 data/news_history/
      ├─ 5. event_cluster.py       事件聚簇（同一件事的多条报道合并，算事件热度）
      ├─ 6. timeline.py            重建跨天事件时间线
      ├─ 7. weekly_report.py       生成周报（持续性榜单 + 要闻主线）
      ├─ 8. export_feed.py         导出 Markdown / llms.txt / RSS
      └─ 重新发布到线上             手机打开即最新
```

**为什么不能纯静态自动更新**：浏览器里的 JS 无法跨域调 GitHub API，也无法自己写文件。
所以数据更新必须在服务端完成——本项目的做法是**GitHub Actions 每天抓取并把数据推回仓库**，
页面只从 CDN 读取结果。这样页面本身无需重新发布，也不依赖任何本地程序常驻。

### ⚠️ 「刷新页面」不等于「更新数据」

| 动作 | 效果 |
|---|---|
| 浏览器刷新 / 点右上角「刷新页面」 | **只重新加载网页**，数据还是上次抓的 |
| 双击 `run.bat` / 等定时任务 08:30 触发 | **重新采集数据**并重新发布 |

看板顶部的**新鲜度提示条**会替你判断当前状态：

- 🟢 **绿色**「本页数据是今天的，已是最新」→ 无需操作
- 🟡 **黄色**「数据日期是 X，不是今天」→ 抓取环节可能失败了，去跑 `run.bat` 或检查定时任务
- ⚪ **灰色**「正在查看历史存档」→ 你在看旧日期，可切回最新

## 两类数据来源：人工研判 vs 自动抓取

看板的要闻区分两种来源，卡片左上各有标记：

| 标记 | 含义 | 内容 |
|---|---|---|
| 🟡 **人工研判** | 人工调研的深度分析 | 含「为什么重要」、置信度、多空结论、风险机会 |
| 🔵 **自动抓取** | 脚本抓的公开快讯 | 四维归类、利好利空、受益板块（**规则推断，可能误判**） |

- 自动快讯的正文默认**折叠**，点「详情 ▾」展开，避免页面过长
- 顶部有**维度筛选**按钮，可只看某一维度
- 若当日没有人工调研，页面自动进入**自动汇总模式**：不显示多空评分结论，
  改用「利好/利空/中性」条数统计代替，并在溯源面板明确标注为 `derived`

### 休市日的处理

节假日 A股不开市时，`market_news.json` 里会置 `"marketClosed": true`，看板会自动：

- 顶部显示橙色 **「A股今日休市」** 横幅
- 「今日盘面」区块**置灰**并打上「以下为上一交易日收盘数据（非当日）」水印，避免把陈旧盘面误当当日行情
- Tab 与标题文案从「今日 A 股要闻」切换为「假期信息汇总」

## 新闻抓取说明

`news_fetcher.py` 从三个公开接口抓取，任一可用即可工作：

| 源 | 接口 | 特点 |
|---|---|---|
| 东方财富快讯 | `np-listapi.eastmoney.com` | 主力源，字段最干净，带关联股票代码 |
| 新浪财经滚动 | `feed.mix.sina.com.cn` | 覆盖面广 |
| 同花顺快讯 | `news.10jqka.com.cn` | 补充 |

**四维分类**：按关键词命中数归入 军事地缘 / 宏观经济·政策 / AI与科技 / 市场资金面。
**情绪判定**：利好 / 利空 / 中性（关键词规则）。
**板块映射**：给新闻对应到 14 类受益板块。

> ⚠️ 以上三项均为**关键词规则推断（derived）**，不是人工判断，可能存在误判。
> 实测情绪判定偏乐观（"上涨""增长"等词命中率高），请结合原文判断。

**fail-closed**：三个源全部失败时不会覆盖旧数据，而是保留上一次的数据文件。

## 项目中文解读怎么维护

`project_notes.py` 里的 `PROJECT_NOTES` 是一张字典表，key 是 `owner/repo`：

```python
"deepseek-ai/deepseek-harness": {
    "name": "一句话说清它是干嘛的",
    "tag":  "赛道分类（会显示成标签）",
    "note": "可选的额外提醒（会显示成高亮提示）",
},
```

- 已收录的项目显示精写解读，**原始英文简介会被降级隐藏**，避免信息重复
- 未收录的项目用 `guess_tag()` 按关键词猜赛道兜底，不会出现空白
- 想给新项目写解读，直接往 `PROJECT_NOTES` 里加一条，重跑脚本即可
- 归档时解读表会**内联进历史文件**，所以切到历史日期也能看到人话说明

## 风险与机会模块

`market_news.json` 的 `riskOpportunity` 块提供三层信息：

1. **risks** — 需要警惕的风险，每条含 `level`（high/medium/low）、现象描述、应对建议
2. **opportunities** — 值得关注的机会，结构同上
3. **checklist** — 操作自查清单

看板按 `level` 自动排序，高关注度排前面。

## 事件聚簇：按「事件」而不是「文章」看

同一件事常被多家媒体各报一遍。实测 60 条快讯里，多组是同一事件的不同媒体版本。
本项目把「文章聚合」升级为「事件聚合」，看板 A股 Tab 的**事件视图**就是它的输出。

- **合并判定**：标题 3-gram 相似度 + 实体重叠 + 主题一致性，四种关系
  （同一次发生 / 同一故事后续 / 汇总类 / 无关）
- **热度按事件算，不按文章算**：48 小时内每个独立来源只算一次，24 小时减半
  → 一家媒体发十篇也只算一次，**真的有很多人在说才排前面**
- **新出现 / 上升**：与上一次运行的事件快照对比得出（不是「今天抓的都是新」）
- **话题块**：同主题的**多条独立**事件归在一起展示（如「美联储动向」今天有 4 条），
  但**不合并**——每条都是独立信息，合并会丢内容

> 逐条的判定依据会写进 `data/events.json` 的 `merge_reasons`，看板上点「为什么合并」可查。

## 重要性评分：五轴 + 噪声压制 + 硬淘汰

早期版本按「关键词命中数」排序，结果是**同一件事被报道得越多分越高**——反向激励。
现已换成三层机制（`news_scoring.py`）：

1. **五轴独立打分**（各 0-10，按 7 类内容类型加权，权重和=10 所以天然 0-100）
   —— 实质份量 / 信息增量 / 证据强度 / 共振面 / 可用性
2. **噪声压制**（轴级降权）—— 活动预告、招聘、预测性表述、传闻、标题党等
3. **硬淘汰**（封顶到门槛之下）—— 明确不该进看板的内容，只降权不够，直接封顶

硬淘汰的五类：纯行情/数据播报、纯海外个股与海外机构观点（与 A 股无直接关联）、
涉及金额过小、会议通知类、领域与市场判断无关（生态/农业科研/平台运营/社会议题）。

**信源分级门槛**：官方一手 T1=46 / 专业快讯 T1.5=50 / 媒体转载 T2=52，
双通道（内容通道 + 结构通道）之和达到 2×门槛才入选。

## 校准闭环：规则到底准不准

关键词规则最怕「凭感觉写的，从没验证过」。`calibrate.py` 就是用来回答这个问题的：

```bash
python calibrate.py
```

它拿 `data/calibration/gold.jsonl`（人工标注的样本，分 该选 / 不该选 / 两可 三类）
去跑现有规则，输出**准确率 / 查准率 / 查全率 / F1**，并列出**错例清单**——
看错例才知道该改哪条规则。同时做门槛扫描（40→90）与开发集/留出集切分，
防止把规则调成「只会做这几道题」。

> **调优轨迹（真实记录）**：初版准确率 **47.6%** → 补上「A股关联度」维度 **52.4%**
> → 加领域无关/小额/会议通知/标题党压制 **61.9%** → 引入硬淘汰 **90.5%**
> → 聚簇感知评测 + 门槛标定 **97.4%**。
>
> ⚠️ 主指标接近满分是**训练集表现**（规则正是在这批标注样本上调出来的）。
> 留出集数字更有参考价值。样本量偏小，规则仍在调整。

## 周报与跨天时间线

单日榜单看不出「谁在持续涨星」。**本周综述** Tab 提供：

- **GitHub 持续性榜单** —— 本周上榜天数 + 星数净增 + 排名趋势
  （「连续 3 天在榜 +3131★」是单日榜单给不出的视角）
- **要闻主线** —— 本周反复出现的主题
- **跨天事件追踪** —— 同一事件逐日进展
  （例：博通为 Anthropic 融资，10-01 报 420 亿 → 10-02 报 600 亿）
- **筛选规则校准结果** —— 上面那套指标的可视化

## 关于「涨星最快」的度量口径

GitHub 官方已取消单日 star 增量接口，trending 页面也没有 API。

本工具用三个可量化维度逼近：

1. **火箭榜** — 近 10 天新建项目的 `stars ÷ 存活天数`，即平均吸星速率，反映爆发力
2. **势能榜** — 半年内新建项目的总星数，反映持续高增长
3. **活跃榜** — 高星且近 3 天仍在推送代码的项目，排除僵尸爆款

**每天运行一次**，`data/snapshots/` 会累积快照，看板从第二次运行起显示真实的「+N ★ 较上次」增量。

## 设计借鉴来源

本项目在设计上参考了两个高星开源项目：

### ZhuLinsen/daily_stock_analysis（65.8k★）

借鉴「LLM + 多源数据 + 定时推送」的整体形状，以及 **决策仪表盘** 式输出——
不只罗列新闻，而是给出核心结论、评分、多空因素、操作提示。

其 A股新闻源方案（Anspire / SerpAPI / Tavily / 博查 / Brave / SearXNG）可作为
本工具未来把 `market_news.json` 自动化的参考。

### HKUDS/Vibe-Trading（34.3k★）

借鉴 **Grounding Gate（数字溯源门控）** 与 **`_provenance`** 设计理念：

- 每个指标标注可信度：`observed`（实测）/ `derived`（推算）/ `failed`（失败）/ `unavailable`（不可得）
- 每个数据文件带 `provenance` 块，说明来源、获取方式、获取时间、逐指标状态、使用警告
- 采集失败时**保留上一次数据**（fail-closed），不用空数据覆盖好数据
- 星数减少的项目不计入增量榜，并记入 warnings

这套机制的价值在于：**让每个数字都能说清从哪来**，避免「默认值静默替换真实值」这类隐蔽错误。

## 可信度标记含义

| 标记 | 含义 |
|---|---|
| `observed` | 接口/原文实测可得 |
| `derived` | 由其他数据推算，非直接观测 |
| `failed` | 获取失败 |
| `unavailable` | 本次不可得（如首次运行无快照可比） |

## 已知限制

- **星数增量需至少运行两次**：首次运行只能建立基线
- **火箭榜是平均吸星速率**，不是真实单日增量（GitHub 不提供该数据）
- **星数有缓存延迟**：Search API 返回的星数可能有分钟级滞后
- **A股要闻为人工调研快照**：不会自动更新，需要重新运行调研
- **未认证 API 限速 10 req/min**：脚本每次运行约 3 次请求，连续运行需间隔
